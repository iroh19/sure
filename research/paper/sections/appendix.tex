Tally across all 8 reasoning strings: 1 accurate, 1 uncodable (empty generation), and 6 inaccurate
in some respect against the true sensor snapshot -- of which exactly 3 (T02, T05, T08, bolded
above) fabricate a specific numeric sensor value that was never in the input; the other 3 (T03,
T06, T07) are inaccurate without inventing a number (an unsupported blanket claim, or an
internally incoherent reading of a plausibly real value).
Note T07: even though the raw model output was unparseable, the safe default (\texttt{ok}) was
still correctly escalated to \texttt{critical} by \texttt{apply\_rule\_override}, because the
override compares the \emph{defaulted} status against the rule engine's, not the raw text -- the
escalate-only safety net functions even when the model's output is garbage.

AQUA-7B's rise from 50\% to 71.4\% raw selection accuracy on the expanded set is not evidence of
improved discrimination -- it follows directly from three of the four new scenarios being
sensor-trend-relevant by design, so a model emitting a single constant answer scores well on any
test whose answer key frequently contains that answer. The constant-answer flag, confirmed true on
both sets, is the metric this paper treats as load-bearing; the raw selection percentage is not.
